# スマホ基本操作の改善と確認（2026-11-16）

## メニューの操作を改善

受付や結果入力中にメニューを開いた際、元の画面へ戻りやすくする。

- 開閉ボタンに状態と閉じ方を表示し、外側タップ・Escapeでも閉じる。
- 閉じたメニューは表示・キーボード・読み上げの対象から外す。
- 開いている間は本体main領域をinertにし、背景の入力・操作とスクロールを防ぐ。
- フォーカスをメニューへ移し、Tab/Shift+Tabでメニューと閉じるボタンの範囲に保ち、閉じるとボタンへ戻す。
- 短い画面ではメニュー自体を縦スクロールできる。PC幅へ変わると背景の制限を解除する。

実装：src/components/layout/sidebar.tsx、src/app/globals.css。画面遷移先、認証・所属店舗・Role判定、DBの処理は変更しない。

## メニューの行き先と押しやすさ

売上・日報の仮リンクは、既存の/admin/business-daysへ接続して「売上・本数」と表示する。実装のない会計・店舗設定は「準備中」の無効項目として保持し、押しても遷移しないリンクと区別する。新しい会計・店舗設定・日報機能を作ったわけではない。実際の画面に未使用の旧見本コンポーネントは変更しない。

スマホではメニュー文字を13pxにし、移動項目・開く・閉じるボタンを44px以上にする。Chrome/WebKit各23項目で、従来の開閉・背景誤操作防止・フォーカス・小画面表示に加え、準備中表示2項目、無効なハッシュリンクがないこと、タップ領域、売上の行き先を確認。売上のリンク操作は実Sidebarとルーターのスタブを用いた画面で確認したもの。遷移先の営業集計画面が本数・売上を表示することはソースで確認し、実DBによる売上数値の受入は未確認。
