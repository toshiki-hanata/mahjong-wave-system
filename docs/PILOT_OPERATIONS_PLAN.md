# 店舗での先行運用から全面運用への計画

更新：2026-11-20。以下は将来の実営業の計画。最新指示では、実データを使って営業外で本運用を想定した受入試験を行い、名簿などは本番にも引き継ぐ。[実データ受入計画](PREPRODUCTION_ACCEPTANCE_PLAN.md)を参照。現公開サイトは架空データでの検証まで完了しており、実データ受入の準備完了とは扱わない。

## 決定済み

- 店舗で実際のお客さんと営業記録を扱う先行運用を開始し、現場で見つかった問題・使いにくさを改善する。
- 年明け（2027年）の全面運用を目標にする。具体的な切替日は未決定。
- 先行運用中は紙とシステムを併用する。紙の記録を止めない。
- 対象はスタッフログイン、営業開始・終了、受付、卓配置・交代、半荘結果・訂正、卓終了・退店、本数/売上/成績。
- 顧客マイページ/パスキー、LINE移行、ポイント自動付与/交換、セット予約は既存の後続計画を維持する。

## 未決定・開始前に必要なこと

| 項目 | 現状・次の確認 |
| --- | --- |
| 設置先・費用 | Vercelで実営業に使う場合はProを想定。月20USD＋超過利用料・税。まだ契約承認なし。店内PCで動かす場合はVercel料金は不要だが、PC常時起動、接続経路とHTTPS等の設定が必要 |
| 本番データ | 架空顧客・試運用アカウントとは分ける。本番用DBと実スタッフを用意し、試運用DBをそのまま実客の登録先にしない。既存DB・実データの削除は行わない |
| MFA | コード/開発検証は完了。実管理者本人の登録と復旧コード保管、外部管理アカウントの確認は未完了 |
| バックアップ | 隔離した復元の成功を確認し、保持期間・保管先・復旧方法を決める。紙併用をDB復元試験の代わりにしない |
| 現場確認 | 実スマホで受付から営業終了、訂正・二重送信・通信断・複数端末を確認する。PCの390px検証とは区別する |
| 初期設定 | 実店舗の卓構成・現行料金・実スタッフの役割を確認。架空データ用の4卓/3ロールを実店舗の数として扱わない |
| 開始判定 | 本番停止ガードを維持。必要な検証と本人確認を完了してから、公開/利用開始を判断する。6時間の目標は安全確認前の公開を約束するものではない |

## 進め方

1. 設置先・費用を決定し、実営業用の環境を準備する。
2. MFA・DB分離・最小権限・復元・実スマホでの通し確認を行う。
3. 紙と併用して先行運用を始める。営業終了時に本数・売上・成績と紙の記録を照合する。
4. 不具合・操作の多さ・迷った導線を記録し、重大度順に修正・検証・コミットする。報告には画面名、操作手順、期待/実際の結果、端末を残し、不要な個人情報や認証情報は記載しない。
5. 年明けの全面運用は、日々の照合・復旧・スタッフ操作が安定したことを確認してから決める。紙の廃止は自動で行わない。

既存の架空データ専用プロジェクトmahjong-wave-trialとNeonの試運用DBは、開発・検証用として保持する。最新の試運転公開指示で、静的な準備中ページだけをProduction枠へ配置し、本体はPreviewへ配置した。この手順を実営業用の公開として扱わない。本体のProduction停止ガードは維持。
