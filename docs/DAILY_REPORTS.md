# OWNER限定：日報・勤務・経費・CSV

2026-11-21。写真は項目と様式の参考だけに使い、写っている実名・金額をDBやGitへ取り込んでいない。

## 使い方

1. OWNERでログインし、メニュー「日報・勤務・経費」を開く。MANAGER/STAFFには表示せず、URL/API/Server Action/DBサービスでも拒否する。
2. 「従業員・時給設定」で給与記録用の氏名・基本時給・時間の丸め・割増を登録。ログイン用Staffアカウントは増やさない。
3. 営業開始日で日報を選び、実際の出勤・退勤を入力。勤務中は退勤を空欄にし、未確定として扱う。休憩打刻や自動控除はなく、必要な場合だけ実際の休憩時間帯を任意入力する。
4. 「経費・売上・アウト等を記録」でセット/飲食/その他売上、店内/イベント経費、現金のサービス料・ゲーム代バック、スタッフアウト、戻し入金、給与支払記録、その他入出金を追加。
5. 「この営業日のCSVをダウンロード」で全体をUTF-8 BOM付きCSVへ出力。「印刷用の日報を開く」→「この日報を印刷・PDF保存」でA4横の用紙へ印刷できる。多い明細は複数ページに続く。

日付の境界は深夜0時で区切らず、BusinessDayの営業開始～終了を使う。営業開始日検索と最近120件の一覧がある。営業終了後の記録・理由付き訂正もOWNERが行える。営業終了操作は勤務入力と連動させず、未退勤は日報に未確定と明示する。

## 給与とアウト

基本時給、丸めなし（実働1分）/支給計算だけ勤務単位の15分切上げ、深夜加算率、日単位時間外加算率・基準分、法定休日加算率を従業員ごとに設定する。実際の出退勤は切り捨てない。深夜帯は店舗時間の22:00～05:00、休日該当は勤務記録でOWNERが指定。深夜と時間外/休日を加算し、法定休日には日単位時間外を重ねない。端数円は勤務ごとの最終額で切り上げる。

- 差引アウト＝当営業日の出金－当営業日の戻し入金。
- 支給参考額＝給与計算額－差引アウト。
- 差引残参考額＝支給参考額－記録済み給与支払額。
- 例：給与9,600円、出金10,000円、戻し入金5,000円なら支給参考額4,600円。さらに1,000円支払記録があれば差引残参考額3,600円。

戻しが当営業日の出金を超える入力、戻しの元となる出金の先行取消は拒否する。過去営業の貸借を自動繰越し・相殺しない。マイナスの差引残は要精算として保持し、勝手に0へ変更しない。勤務が未確定なら給与と差引額は未確定とし、0円で確定しない。

これは日報用の参考計算である。週・月単位の時間外（60時間超を含む）、税・社会保険、就業形態、控除の適否を含む法定給与の確定エンジンではない。アウトの相殺・振込は自動実行しない。運用前に労務上の取扱いを確認する。参考：[労働時間の切捨てに関する厚労省資料](https://www.mhlw.go.jp/content/11200000/001310369.pdf)、[割増賃金](https://www.check-roudou.mhlw.go.jp/qa/roudousya/chingin/q3.html)、[貸付金と賃金相殺のQ&A](https://www.startup-roudou.mhlw.go.jp/qa/zigyonushi/chingin/q12.html)。

## 集計対象

フリーはCONFIRMEDの半荘1卓1回を1本とし、保存済み単価を合計。着順のみの結果も含め、訂正前のGameは除外する。フリー売上は手動で重複入力させない。セット料金や飲食は今回の日報では手動記録であり、予約・在庫・決済は追加しない。

来店は対象営業日に結び付いたVisitを時刻順で表示し、再来店明細を残しながらCustomerの実人数を重複除外。participantStaffIdがあるスタッフ参加は来客から除く。営業日が付いていない古い記録を推測で配賦しない。名前は現在の顧客名簿情報を表示する。勤務の氏名・計算設定は記録時のスナップショットを保持。

日報収支＝売上記録＋その他入金（戻し含む）－現金支出記録。未入力の入出金や未払給与、税等を含む利益・レジ残高とは区別する。取消明細を保持し集計だけから除外。元の金額を上書きせず、理由を付けて取消→必要な記録を再入力する。勤務日時・明示的な給与設定再読込も変更前後・理由・担当を監査し、取消した勤務は履歴を残す。

## 安全性

新モデルDailyReportWorker/Shift/CashEntry/Requestと追加migration20261121200000_owner_daily_reports。既存テーブルへのデータ更新なし。全書込でStoreロック→有効OWNER・店舗・sessionVersion再確認→入力検証→同時/重複/版管理→監査を一つのトランザクションで実行する。

入出金の金額に実行ロールのUPDATE権限を付けず、取消日時/理由の列だけUPDATE可。送信履歴はSELECT/INSERTのみ。削除しない。CSVはno-store/private、Cookieで店舗を決定、MFAを含む実セッション検証、共有クォータ、Origin/Sec-Fetch-Site確認、出力監査、固定ファイル名。CSVの文字列は数式開始文字を無害化し、数値は数値のまま負数を保持。引用符・改行を適切にエスケープする。[OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection)、[RFC4180](https://www.rfc-editor.org/rfc/rfc4180)。給与・名前・CSVを公開ファイルやブラウザ永続ストレージへ保存しない。

最大500従業員、1営業日500勤務/2,000入出金/5,000来店/5,000確定半荘、CSV4MBまで。上限超過は省略せず停止する。正式運用規模で見直す。
