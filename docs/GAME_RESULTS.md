# 半荘結果：点数入力と着順のみ（2026-11-21）

ユーザー承認：着順のみでも本数・平均順位・トップ率・売上には含め、点数・成績スコアを未入力として点数系集計から除外する。

## 使い方

卓一覧の「半荘結果を入力」から、次のどちらかを選ぶ。

- 「点数を入力」：4人の最終持ち点を入力。合計点・点数単位・マイナス可否・同点時の座席優先を従来どおり検証し、順位とスコアを計算する。
- 「着順だけ入力」：上から1位→2位→3位→4位に異なる4人を選ぶ。点数なしで確定できる。

「保存して次の半荘へ」「保存して結果を確認」は両方で利用できる。入力方式を切り替えても同じ画面内の入力を保持する。保存済み結果・半荘履歴・点数入力時の着順プレビューは1位から4位の順。元の座席番号は変えない。

後から点数を追加する場合はOWNER／MANAGERが詳細の「結果を訂正」で点数入力へ切り替え、理由を入れて保存する。元記録・担当・理由を保持し、訂正版だけを有効にする。STAFFは従来どおり訂正できない。

## 集計とデータ

- 点数なしはfinalPointsとscoreScaledを両方NULLで保存。0点・0スコアで代用しない。DB制約で片方だけNULLを拒否する。
- rank、顧客・来店・卓・元座席・営業日・その時の半荘単価を保存する。ruleSnapshotにPOINTS／RANK_ONLYの入力方式も記録する。
- 本数・売上・順位回数・平均順位・各率・連勝は、着順のみの有効結果も対象。
- スコア合計は点数入力済みのみ、スコア平均は点数入力済み本数を分母とする。着順のみしかない場合は「スコア未入力」を表示。
- スコアランキングの規定打数は点数入力済み本数で判定。順位系ランキングは着順のみも含む全有効本数で判定する。規定未達欄には該当指標の対象本数を示す。
- 訂正では元の営業日・単価・effectiveAtを継続し、元記録を集計対象から除外する。点数の補完で本数・売上が増えない。
- prisma/migrations/20261121034000_rank_only_resultsは既存2列のNULL許容と対応するCHECK制約だけを変更。既存の点数・成績・名簿を更新するDMLやseedは含まない。

## 運用上の注意

着順のみの記録ができた後に、NULL非対応の旧Previewへ戻すと旧画面が表示できない。障害時はこの版のNULL対応表示を残して修正し、入力を止めるなどの方法を取る。NULLを0で埋める、過去の記録を削除する、DROP NOT NULLの逆操作で戻す方法は使わない。

実名簿を保持する試用DBへQA・seed・resetを再実行しない。DBテスト・自動画面検証は専用schema-only環境だけで行う。本人の実機受入・本番移行・バックアップ復元・Hobby利用条件の確認は別途必要。
