# 特典ポイント台帳：手動調整・取消（2026-10-31）

入口：顧客詳細の「特典ポイントの残高・履歴へ」→ `/admin/customers/[id]/points`。

## 実装済み（P01-a）

- 全スタッフが自店舗の通常会員の記録済み残高・履歴を確認できる。無効会員は履歴だけを表示し、スタッフ参加用会員は対象外。
- OWNER／MANAGERだけが、追加／減算・ポイント数・理由を入力して手動調整できる。一般STAFFは操作UIとServer Action、DBからの現役割確認で拒否する。
- 元の調整を取り消す場合は、理由を付けた逆方向の記録を追加する。元の記録を上書き・削除しない。取消の再取消は提供せず、必要な修正は理由付きの別調整として記録する。
- 残高は全台帳の増減の合計。最新50件の表示と残高全体の計算は別。取消済みか、担当・理由・日時・記録後残高を履歴で確認できる。
- 残高が不足する減算・取消、整数の保存範囲を超える操作、残高が変わった古いフォームを拒否する。負の残高を許す対局訂正・精算の扱いは未確定であり、今は実装していない。
- リクエストキーは店舗内で一意。同じ内容の再送は二重記録せず、別の対象・量・理由・担当へ流用した場合は拒否する。
- 店舗ロックで変更を直列化し、対象会員・担当者・取消元は複合外部キーで同一店舗・同一会員に制約する。記録とAuditLogは同一トランザクション。
- DBトリガーでも台帳のUPDATE／DELETEを拒否する。SQLを直接使う運用でも台帳を編集せず、訂正は追記を原則にする。
