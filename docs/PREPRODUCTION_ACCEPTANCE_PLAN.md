# 実データでの営業外受入試験

更新：2026-11-20。ユーザーの最新の説明・回答を記録する。

## 決定済みの利用方針

- 現段階は、実データを入力して、本運用に使えるか・操作しやすいかを確認する営業外の受入試験。営業の正式記録として運用を開始する段階ではない。
- 実際のお客さんの名簿などは、本番運用に切り替えた後も引き継ぎたいと本人が回答した。使い捨ての架空データとして扱わず、移行・復元が必要な保持対象とする。
- 試験中に作る対局・売上等の記録は、本番の営業実績へ自動的に混ぜない。名簿と試験実績の扱いを分け、具体的な分離・移行方法を準備する。
- 費用は本人が実利用の段階で判断したいという意向を保持する。有料契約・無料トライアルを勝手に開始しない。
- 年明けの全面運用と紙併用は将来の計画として保持する。今回の説明を実営業の開始承認と扱わない。

## 現在の実装・検証との区別

[公開記録](TRIAL_DEPLOYMENT.md)の現行サイトは、架空顧客・試運用アカウントの専用DBと認証付きPreviewで検証したもの。実際の顧客データの移行・投入は今回行っていない。実データを引き継ぐ受入環境の準備完了を意味しない。

現行の営業開始・結果確定・売上集計は、そのDB内の通常の記録として保存される。「営業外テスト」と呼ぶだけで、アプリが試験実績を自動除外する機能は追加されない。具体的な移行方法と確認手順が決まるまで、現行DBをそのまま本番へ昇格・複製する扱いにはしない。

## 次に整えること

| 項目 | 完了条件・現在状態 |
| --- | --- |
| 保持するデータ | 名簿などを本番へ引き継ぐ方針は決定。具体的な項目・元データ・顧客ID/コードの維持・重複照合・取込手順を確認する。既存ポイント残高や成績までの移行は今回確定していない |
| 実データと自動テストの分離 | 架空データ用QA/fixture/seedと、保持する実データの保存先を分ける。実データのDBを既存のQAスクリプトへ指定しない。現行QAは既存の架空データプロジェクトID・Host・DBマーカーに固定されている |
| 名簿と試験実績の分離 | 試験対局・売上等を本番集計へ取り込まず、合意した名簿だけを移す等の方法を決めて検証する。本番への切替時に、顧客と参照関係を壊さないことを照合する |
| 保管・復元 | 保持対象を確認したバックアップを取得し、隔離した保存先へ復元・照合できることを確認する。実データが入ったDBはreset/seed/自動クリーンアップの対象にしない。現時点で隔離復元は未完了 |
| 本人と権限 | 実際の利用者ごとのアカウント・権限、OWNER/MANAGERの本人MFA登録と復旧コード保管、基盤管理アカウントMFAを確認する。架空アカウントでの検証成功とは分ける |
| 利用条件 | 現契約はVercel Hobby。公式資料では個人・非商用向け。店舗導入のための実データ受入試験が該当条件内かは未確認。営業に使わないという説明だけで適用可否を断定せず確認する。課金操作はしない |
| 実機受入 | 実iPhone/Android、通信断、複数端末、連続操作、保管・復元・引継ぎの確認を行う。PC上のChrome/WebKit 390px成功は実機受入の代わりにしない |

## 今回の変更範囲

方針とバックログの更新のみ。DB・実顧客・認証アカウント・契約・デプロイ・アプリコードを変更していない。現行の専用DBや架空データも削除・初期化しない。保存先と移行の具体化前に実データを取得・投入しない。
