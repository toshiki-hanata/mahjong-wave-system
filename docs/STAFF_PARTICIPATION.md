# スタッフの着席・成績・参加本数（2026-10-31）

## 店員の操作

1. 営業を開始し、`/admin/visits`「受付・来店中」の「スタッフを参加させる」を開く。
2. 自店舗の有効なスタッフを選び、待機へ追加する。参加済みのスタッフを繰り返し追加しても、来店・参加を二重作成しない。
3. `/admin/tables`で、お客さんと同じ座席選択からスタッフを含む4人を配置する。「スタッフ」の表示で顧客と区別する。
4. 通常どおり半荘結果を入力する。1人交代・席替えにも対応する。過去の参加者・結果は変更しない。
5. スタッフの参加終了は、卓終了または交代で待機に戻してから、受付画面の「参加を終了」を押す。
6. `/admin/staff-games`「スタッフ成績・参加本数」で、最近30営業から選んだ本数・通算本数・成績・最近の対局を確認する。

OWNER／MANAGERは自店舗のスタッフ全員、STAFFは自分だけの本数・成績を確認できる。URLや入力で指定したrole・staffIdを権限根拠にしない。

## 記録と集計

- Staffと店舗内で一意に対応する専用Customerを内部で使用し、既存のVisit・座席・GamePlayerResultへ参加させる。同じ名前の顧客と統合しない。
- スタッフ用会員を通常の顧客検索・顧客編集・公開プロフィール・顧客個人成績の入口へ混ぜない。
- スタッフも顧客と同じ料金を支払う前提。店舗のフリー本数はスタッフが何人いても1卓・半荘1回につき1本。保存済み単価で売上を記録し、スタッフの人数分を加算しない。
- 各スタッフには、参加した有効な半荘1回を1本として記録する。訂正前と訂正版を重ねて数えない。
- スタッフは当面、顧客向けランキング・特典ポイントの対象外。方針は`src/features/staff-participation/participant-policy.ts`に集約し、将来変更の際も履歴を捨てない。ポイント機能自体は未実装。
- 受付の待機／対局中人数にはスタッフを含め、来店・参加人数と表示する。営業別の顧客実人数・来店件数には含めない。
- スタッフへのゲーム代バックの単価・精算方法は未確定。本数と成績を記録する段階であり、返金額や給与処理は実装していない。

## 制約・認可・再送

- 自店舗の有効なスタッフのみ新規参加・着席・交代可能。二重参加・二重着席を防ぐ。
- スタッフアカウントを無効化した後は新しく着席させない。既に対局中の場合は結果保存・卓解放・参加終了を可能にし、履歴を維持する。
- 営業中だけ参加できる。対局中の直接参加終了は禁止。未終了のスタッフ参加が残る間は営業終了を禁止する。
- 参加操作のリクエストキーは監査へ記録する。同じキーを参加終了後に再送しても新規参加を開かない。キーの対象者が異なる場合は拒否する。
- 店舗→スタッフの共通ロック順序で、参加／無効化・座席変更の競合を扱う。専用Customerの店舗・Staff対応は複合外部キーと一意制約でも保護する。
- 変更・Visit・監査は同一トランザクション。途中失敗は取り消す。
