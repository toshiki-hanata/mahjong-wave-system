# 関係者向けの説明手順

約8分。説明モードを開き、章から操作へ進みます。複雑な検証は説明後に行います。最初に「営業中の見本」を読み込んでください。

|章|目安|説明・操作先|
|---|---|---|
|1 麻雀ウェーブとは|30秒|受付・卓・結果・営業終了を、店員がスマホで迷わず扱うためのシステムです。 [麻雀ウェーブとは](../index.html#/explain?chapter=0) → [dashboard](../index.html#/dashboard)|
|2 現在できていること|40秒|フリー営業、名前だけ受付、卓操作、結果訂正、内部成績、スタッフ参加が動いています。 [現在できていること](../index.html#/explain?chapter=1) → [all-screens](../index.html#/all-screens)|
|3 フリー営業を体験|70秒|営業を開き、4人を配置し、結果を入れて締めます。売上は本数×単価です。 [フリー営業を体験](../index.html#/explain?chapter=2) → [demo-guide](../index.html#/demo-guide)|
|4 会員・受付|40秒|同名を勝手にまとめず、既存会員を確認。紙名簿の照合も体験できます。 [会員・受付](../index.html#/explain?chapter=3) → [customers](../index.html#/customers)|
|5 成績・ランキング|40秒|保存・訂正が個人成績とランキングへ反映。正式な計算ルールは導入前に確認します。 [成績・ランキング](../index.html#/explain?chapter=4) → [ranking-month](../index.html#/ranking-month)|
|6 ポイントとLINE|50秒|手動台帳は実装済み。LINE継続と独自管理の2案は、分けて検討します。 [ポイントとLINE](../index.html#/explain?chapter=5) → [line-options](../index.html#/line-options)|
|7 QR受付を比較|40秒|来店時に読む案と、退店時の対面確認を残す案を実際に切り替えます。 [QR受付を比較](../index.html#/explain?chapter=6) → [qr-compare](../index.html#/qr-compare)|
|8 セット・予約|35秒|代表者と卓で利用を管理し、予約の時間重複を防ぎます。製品では開発予定です。 [セット・予約](../index.html#/explain?chapter=7) → [reservations](../index.html#/reservations)|
|9 スタッフ・店舗運営|40秒|本走の記録に加え、番責・前貸し・経費・在庫・日報の将来像を確認します。 [スタッフ・店舗運営](../index.html#/explain?chapter=8) → [staff](../index.html#/staff)|
|10 今後の開発|30秒|現場の使いやすさを優先し、本人認証・ポイント・セットを順に仕上げます。 [今後の開発](../index.html#/explain?chapter=9) → [roadmap](../index.html#/roadmap)|
|11 未解決の問題|35秒|LINEの自動連携可否、本人確認、正式料金、AWSの必要性などは確認が必要です。 [未解決の問題](../index.html#/explain?chapter=10) → [issues](../index.html#/issues)|
|12 導入前の確認|30秒|実スマホの通し操作、バックアップ・復元、個人情報保護、本番公開を確認します。 [導入前の確認](../index.html#/explain?chapter=11) → [launch-checklist](../index.html#/launch-checklist)|

## 操作の例

- 見本の1卓で35,000／28,000／22,000／15,000を保存。本数と売上が1本・2,500円増えることを確認。
- メンバー交代と結果訂正を行い、過去4人・旧結果が保持されることを説明。
- LINE案AはWaveへ自動受付しないこと、案Bの移行は未検証であることを伝える。
- 公開同意を外しても本人の成績は見られることを確認。
- 一日の通し体験は「最初から」から。5人以上を受付し、交代後の退店も忘れない。
- セット終了・全員退店・スタッフ参加終了が済まないと営業終了できない。
